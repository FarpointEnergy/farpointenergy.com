# Remaining browser acceptance

This suite covers the outstanding BROWSER-01–04, UX-02 and browser portion of PERF-03 without repeating the earlier quotation/preview suites. All network is confined to loopback fixture servers or intercepted FormSubmit requests. No real RFQ or hosted collector request is sent. Every run and case uses a unique evidence directory; raw synthetic collector/provider requests, ACKs, failures, screenshots and traces are retained without replacement.

Run the fixture/parser unit tests with `node --test analytics/tests/browser/*.test.mjs`. Actual browser execution requires OpenSSL, Playwright 1.62.1 with its engine dependencies, Openbox, xdotool, x11-utils and a virtual display on Linux:

```sh
FARPOINT_ACCEPTANCE_ENGINES=chromium FARPOINT_ACCEPTANCE_HEADED=1 xvfb-run --auto-servernum bash -c 'openbox & manager_pid=$!; trap "kill $manager_pid 2>/dev/null || true" EXIT; node analytics/tests/browser/check-acceptance.mjs /absolute/private/evidence'
```

The separate `Remaining browser acceptance` workflow runs Chromium, WebKit and Firefox. Headed browsers under Xvfb/Openbox provide actual foreground/background changes by minimizing and restoring the active test window. Before any window action, the fixture verifies the visible quotation-page title and confirms its process is a descendant of this test runner. The test requires real hidden/visible transitions and a received background beacon; it never overrides `document.visibilityState`. Fresh persistent profiles test close/reopen; they never use or clear a real user profile. Offline/reconnect uses the browser network control. Two same-origin tabs enqueue distinct events and receive newer ACKs before older ones. Storage denial is explicitly injected into a fresh browser context; quota exhaustion fills that context's localStorage using new keys and progressively smaller values until even the smallest new item is refused, with a 32 MiB attempt cap. Existing event bytes must survive and the quotation form must remain usable. A separate bounded 1,000-event backlog must drain without eviction, with exact local receiver reconciliation. This does not measure hosted archive capacity.

Persistence/offline/reopen runs on all three engines. The separate native-background case starts a fresh owned Chromium process/profile and attaches to its default context through the documented `connectOverCDP({noDefaults:true})` option. This prevents Playwright from enabling forced focus in the first place; earlier attempts to turn it off afterward remain failed evidence. The debugging endpoint is loopback-only, and the browser trusts only the ephemeral fixture certificate's SPKI, without a general certificate bypass. The fixture records the owned process, browser build, command arguments, default-context mode, actual window-manager state and actual browser visibility. Real OS minimization/restoration, a retained beacon event and its later acknowledged fetch are required. Firefox and WebKit native background visibility remain unverified; prior native beacon delivery does not establish visibility coverage. The approved BROWSER-01 scope requires a complete actual background/retry sequence, without a universal engine/OS requirement. Browser binaries and installed drivers are unchanged.

The workflow now defaults to the two remaining lifecycle cases. Set `FARPOINT_ACCEPTANCE_CASES` (or the manual workflow's `case_names` input) to a comma-separated case list, or `*` for all cases. The report records selected cases explicitly; omitted cases are never marked passed. Earlier verified cases are reused with their exact source/evidence bindings. In particular, PERF-03's three baseline/current pairs from run `40495470676` use the originally declared bare-Xvfb profile and a reviewed trace-parser correction. Later Openbox traces from run `40497595614` retain unresolved native-task attribution as `UNKNOWN`; they are additional environment evidence, not relabelled passes.

Absent instrumentation cases cover JavaScript disabled, blocked tracker, blocked collector and an injected tracker-script startup exception. Blocked cases must prove the intended block occurred; an enabled tracker with a blocked collector must retain correlated form-success events locally and deliver no collector request. Native and enhanced provider requests are intercepted and recorded. A pass proves browser transport/fallback behavior, not inbox delivery. The keyboard scenario uses only Tab, Shift+Tab, Enter, ArrowDown and keyboard text input through navigation, reference selection, required-field errors, technical details, provider error, email fallback and success. The retry path moves backward from the error email link to the submit button instead of tabbing out into browser chrome. Visible controls must have names from associated labels or valid ARIA naming, with the source preserved. Browser media emulation checks reduced-motion behavior.

PERF-03 captures three alternating baseline/current pairs in fresh Chromium contexts. The chosen profile is iPhone 13 viewport/touch emulation (390×844, scale 3), 4× CPU slowdown, 150 ms latency, 1.6 Mbit/s download and 750 kbit/s upload on Linux. It is neither physical iOS Safari nor a calibrated handset. Baseline replaces the tracker response with an empty script and disables its configuration; all other site assets and actions are unchanged. Current executes the exact tracker source with synthetic collection. External Google Fonts are blocked in both variants. The report preserves navigation/resource timings, deferred-script and synchronous-XHR observations, complete Chrome trace streams and source hashes.

The trace analyzer conservatively counts an entire main-thread task when synchronous trace events or CPU stack samples attribute work in it to `tracker.js`; this is not tracker self-time. Tasks over 50 ms fail the chosen-profile target. Excluding an unrelated long task requires mapped CPU samples across its start, interior and end with no gap over 5 ms. Unique start/end user-timing marks must bound the complete scripted interaction and final flush; explicit no-data-loss completion metadata is also required. Missing attribution, malformed profiles, trace data loss or unsupported trace formats are `UNKNOWN` and cannot pass. Sampling is observational; the report is evidence for the measured runs, not a universal performance guarantee. Parser tests cover nested execution, clocks, malformed/missing evidence, sparse sampling, unrelated tasks and boundary cases. Trace bytes are appended as each stream chunk arrives, preserving partial streams on failure. The source gzip target is 15 KiB. A held deferred tracker response separately proves the browser can parse/display the form and accept input before that script finishes loading.

Chrome can record out-of-order CPU samples using signed time deltas. Following Chrome DevTools, the parser accumulates those exact deltas, then stably sorts timestamp/sample pairs while retaining original provenance; it never clamps negative deltas or fabricates samples. Unfinished execution events that begin strictly after the required end marker remain explicit post-span diagnostics. Unfinished events crossing the measured interval still prevent a pass, and complete enclosing-task durations are never clipped.

Fixture unit tests verify exact-byte journaling before parsing or responding, append-only evidence writes, controlled dropped responses, out-of-order replies, and bounded teardown both before and after a held response is registered. All browser contexts, fixtures and outstanding evaluations have bounded cleanup; late page/route/drain errors fail the final result.
